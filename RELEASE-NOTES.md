# Dashboard performance update

This release supersedes the dashboard shortcut description below: CAPI is removed from all four dashboards; its existing authorized integration page is unchanged.

**Cause reproduced:** The timestamp observer ran a document-wide table scan and replaced already-formatted timestamps with identical text nodes. Each write scheduled another scan and woke unrelated button/icon observers. With one timestamp in a Chromium dashboard fixture and no incoming traffic, a three-second sample recorded 23 full timestamp scans, 46 export-button queries and 23 icon queries. Even without timestamps, replacing the clock node every second triggered scans. After the fix the same timestamp sample recorded zero full timestamp scans, two export-button queries and one icon query during initial decoration, without a recurring scan loop.

**Fix:** Localize only changed subtrees/cells, skip identical output, reuse UK time formatters, and update clock character data in place. Number-copy decoration watches its table rather than the entire document. Dashboard reads run concurrently; overlapping dashboard loads share the pending refresh. The earnings chart reuses the summary response. Monthly data survives subsequent hero updates; chart-tab clicks replace only the graph. Secondary-page preload work no longer runs on dashboard startup, and integration credentials load when the integration page opens. Sidebar content performs one width adjustment rather than animating repeated page reflows. No intentional changes to dashboard metrics or the live Client recent-SMS probe.

**Backend audit:** Compared the prior release to repository baseline 7c65a0e. The prior changes covered requested number filters/export, provider metadata and association, unified creation, and the fix allowing explicitly authorized HTTP sources when the legacy text list is empty. Reverting those would undo requested features. No change was found to number import, payload processing, forwarding or SMPP protocol code. All backend files in this performance release are byte-for-byte identical to the preceding ZIP. No additional migration, dependencies or deployment commands.

**Tests:** Isolated SQLite and Chromium sessions for Admin, Manager, Agent and Client: dashboard data, shortcut removal, graph tab changes without hero replacement, desktop/mobile sidebar and navigation, and display of the fixture number. Integration pages mounted on demand for the authorized roles. An unapproved HTTP source was denied; after authorization a test SMS was received, stored against the expected allocated number and role hierarchy, and returned by the SMS report. SQLite integrity check passed. These are fixture tests, not measurements from a live carrier or the production server.

- Admin Numbers combines four pending selectors on explicit Filter. Combined selection is carried into the paginated query, CSV filter and filtered deletion query. Delete by Range remains separate. The table is compact; the records selector and search field share a grid row even when export controls wrap. Selection checkboxes and unassignment actions were retained.
- Numbers displays Admin's existing provider-cycle rate and downstream effective rate. Manager and Agent see their existing role-specific incoming effective rate and the stored `agent_rate` or `client_rate`, respectively. No payout computation was moved to the browser. Missing outgoing values are not replaced by invented rates.
- SMS Detail's selector containers previously had no actual select elements for the existing population functions. The role-specific selectors now receive the existing scoped data. Provider contact information is optional and separate from SMPP credentials and the IP explicitly authorized for HTTP. A blank provider name falls back to the SMPP connection name or HTTP address. Provider and connection are saved together under a SQLite savepoint. Existing edit, start/stop, protocol validation and provider-sync routes remain. Legacy records still resolve by their original name associations; new records have an explicit provider ID.
- HTTP incoming previously rejected an explicitly allowed source whenever the separate legacy IP text field was empty. It now checks the existing combined allowlist. An empty allowlist denies access, and the global integration enable/disable switch still applies. Contact IPs alone do **not** authorize traffic.

## Deployment and migration

1. Use Node.js 20 or newer. Before deployment, stop the production writer/process in a maintenance window and take a **full, restorable SQLite backup**, including any required WAL state, plus existing configuration, uploads and secrets. The selective business backup is not a substitute for a full rollback image.
2. Unpack the project into a new release directory. Retain your existing `.env`, `JWT_SECRET`, storage paths and service configuration. Check that `DB_FILE` resolves to the intended **existing** database (prefer an absolute path). Do not replace it with a test database or inadvertently initialize an empty one. Preserve the existing reverse-proxy configuration; only trust client-IP headers set by your trusted proxy.
3. From the project root run `npm ci`, then `npm start` (or restart the existing process-manager service). There is no frontend compilation step and no new runtime dependency.
4. The existing startup schema initializer adds `ams_providers.contact_email`, `ams_providers.contact_ips`, `activity_ips.provider_id` and `smpp_connections.provider_id` if missing. No manual SQL, rate backfill or connection recreation is required for this update.
5. On staging first, sign in to all four roles, match a known number against its pre-upgrade rates, check provider totals, and verify reconnect/authorized delivery with your carrier. A service restart can interrupt live SMPP sessions. For rollback, stop the updated service and restore the previous release and its matching backup; restoring a database discards writes after that backup, so reconcile those separately.
